# 核心目标

确认基线：2026-10-25 用户本轮明确列出的六项要求；无需重复询问同一范围。
前序会话只取回了用户消息，助手正文不可读，不据此补造产品决策。

## 产品定位

建设公开、免费、只读的 AI 与云资源福利、免费额度和限时活动信息展示站。
核心价值是可靠的信息判断，而不是承诺用户一定能获得额度。
站点免费访问不代表研究模型、云运行或基础设施永远不消耗额度。

## 核心质量要求

1. 可追溯发现：保存发现链接、发现时间和官方活动入口。
2. 官方核实：记录证据链接、简短证据摘要、读取时间和核实结论。
3. 可判断领取：明确资格、地区、额度、计费周期、信用卡及自动续费条件；
   未披露内容写明未知，不能补全猜测。
4. 时间透明：区分活动起止时间、个人额度有效期、最后核实与下次复核时间。
   无公开截止时间不等于永久有效。
5. 状态透明：待核实、有效、即将开始、已过期、已失效；复核逾期单独标识。
6. 历史可查：结束信息进入历史区；保留每次核实结论与 Git 变更记录。

## 已确定技术方向

Codex Scheduled Tasks + Resource Research Skill 负责发现、核实与更新。
GitHub 仓库保存 JSON；GitHub Actions 测试构建并发布到 Pages。
前端采用 React + Vite + TypeScript，无业务后端和用户数据库。
优先验证针对远端仓库的云端无人值守更新，不能用桌面定时运行代替验收。

## 明确不做

不做用户线索提交、订阅通知、账号系统、评论、个人收藏。
首阶段不做付费 API、资源自动领取、账号注册代理、营销转化或复杂管理后台。

## 成功标准

任何展示条目均能追溯至官方证据并读到限制条件；无证据不标有效。
定时更新必须有真实运行记录、远端提交及无人干预证据才能标记通过。
没有新发现时保持数据不变；失败时保留最后可信记录，不伪造复核成功。

## 2026-10-25 新增的采集与发布约束

监控 LINUX DO、NodeSeek、NodeLoc、AI Spoils、AIdeal、线报酷、AI 福利雷达、掘金与厂商官网；重点覆盖 VPS/云服务器/云电脑/海外算力、AI/API/编程额度、云券、新用户和限时活动，并追踪华为云、InstaBox、LightVela、CodeBuddy、Muse 等重新开放和额度变化。

以独立 Collection Publishing Skill 指导发现→官方核实→JSON 更新→校验→Pages；新增活动介绍、福利价值、领取入口、费用风险、核实时间和可信程度字段。仅社区线索不得直接标记为有效。电脑关机仍执行、定时不消耗 Codex 模型额度是正式调度的优先验收目标，优先 GitHub Actions 非 LLM 规则采集；不得把技能文件或已有 Pages 工作流误称为采集任务已运行。
