# FreeStack Radar 分阶段实施计划

目标：落地可信资源目录的本地基础，并将云端自动更新作为独立实测门槛。
架构：React + Vite + TypeScript 消费 JSON；Ajv 校验；Codex Skill 研究；Actions 发布。
按用户已确认范围在当前工作区执行，不新建隔离工作区，不自动推送。

## 阶段一：本地基础（本轮）

1. 检查目标不存在，初始化 Git，写入 README 和四份目标/架构/风险文档。
2. 写入 `tests/resources.test.ts`，运行测试确认缺少实现时失败。
3. 建立 `schema/resources.schema.json`、`src/resources.ts`、`scripts/validate.ts`，
   验证重复、未知期限、缺证据、无效时间、过期与历史状态。
4. 实现 `src/App.tsx`、样式及空态，正式 `data/resources.json` 保持空数组。
5. 建立 `.agents/skills/resource-research/SKILL.md` 和 `automation/research-prompt.md`。
6. 建立 `.github/workflows/ci.yml` 和受控 Pages 工作流。
7. 运行 `npm run check`、浏览器检查、Skill 检查；记录结果，审查 Git 文件并本地提交。

验收：本地构建通过，正式数据无虚构，文档与代码一致；报告真实路径与 Git 状态。

## 阶段二：云端可行性门槛（未完成）

按 `docs/risks-and-validation.md` 的步骤实测登录账户、云端触发、远端写入。
验收必须包含真实云端运行标识、提交 SHA、重新读取校验及无人干预证据。
若受限，记录具体阻碍。不得默认转为付费 API，也不以本机后台任务冒充云端。

## 阶段三：真实内容试运行（未开始）

先研究少量官方资源，逐条人工对照额度、资格、时效和证据。
使用 Skill dry-run；修订结构后再授权远端更新。
验收包括成功核实、抓取失败、过期归档、无变化不提交和并发冲突五类情况。

## 阶段四：发布与观察（未开始）

用户授权远端后创建或连接仓库、推送、启用 Pages，验证子路径和移动端展示。
