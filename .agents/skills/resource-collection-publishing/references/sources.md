## 已实测可读路径（2026-10-26 验证）

两家主源都用 Cloudflare 拦直连：普通 HTML 与 Discourse JSON API 一律 403 `Just a moment...`。实测可用的是**订阅源端点 + 只读渲染代理**，不需要登录、不绕过验证。

| 站点 | 可用端点 | 实测结果 | 说明 |
| --- | --- | --- | --- |
| LINUX DO · 福利羊毛 | `https://linux.do/c/welfare/36.rss` | 200，25 条 | **首选**。分类 RSS（`welfare` 分类 id=36），含标题、`/t/topic/<id>` 链接、`pubDate`、首帖摘要 `description`、`dc:creator`、`discourse:topicClosed/Pinned` |
| LINUX DO · 全站 | `https://linux.do/latest.rss` | 200，30 条 | 备用；每条带 `<category>`，可只留“福利羊毛”条目；`/c/resource/14.rss` 为上级“资源荟萃”分类，25 条 |
| LINUX DO · 正文 | `https://r.jina.ai/https://linux.do/t/topic/<id>` | 200，Markdown | 帖子正文、发布时间可读；仅在 RSS 摘要不足时按需调用 |

| NodeSeek · 其余 | `www.nodeseek.com/*`、`/api/*`、`/rss`、`r.jina.ai` 代理 | 403 / 被封 | 直连、JSON API、Jina 匿名代理全部不可用（Jina 因该域名历史滥用被封至 2027）；NodeSeek 只能靠 RSS 标题+摘要，看不到完整回帖 |
| 其他聚合站 | AI Spoils、AIdeal 等 | 可读 | 仅作发现线索，仍需回到厂商官网核实 |

使用约束：

- 请求头带常见浏览器 `User-Agent`；LINUX DO 连续请求会返回 **429**，实测 20–30 秒间隔可恢复，一次运行不要超过约 5 次拉取，分页 `?page=N` 可接受但不保证返回不同内容。
- RSS 摘要足以判断相关性；**不得**把摘要当成官方条款，标 `active` 仍需厂商官网证据。
- 需要 NodeSeek 帖子全文时，只能作为“线索待人工确认”记录，或换用已授权的浏览器控制能力在真实浏览器中人工查看，不引入破解/绕过方案。
- 站点结构可能变化；上述路径每次运行须复核，失效即回到 Jina 只读代理或 Firecrawl（仅在完全无法访问时，见 AGENTS.md）。

## 监控主题与筛选准则

- **VPS / 云服务器**：free VPS、超低价/特价实例、云主机、海外节点、免费试用；核对实际 CPU/RAM/磁盘/流量/地区、周期和原价/续费价格，不仅凭宣传价格判断。
- **云电脑 / AI Agent 沙箱**：云端桌面、远端工作空间、Agent 代码执行沙箱、隔离容器；核对免费时长、资源配额、并发限制、存储持久性及潜在付费。
- **AI 编程工具**：Coding Agent、IDE、CLI、代码助手、免费 Pro 体验、开发者计划；核对免费期、可用模型与配额。
- **模型 API 免费额度**：API Credits、Token、调用次数、免费试用与模型访问资格；核对额度单位、有效期、限速和绑卡条件。
- **代金券 / 官方开发者福利**：云券、开发者赠金、学生/开源开发者福利、新用户与限时活动；核对抵扣范围、资格与地区。

词组包括中文/英文及常见组合：免费、限免、超低价、特价、VPS、云服务器、云电脑、Agent Sandbox、remote workspace、Coding Agent、API credits、token、voucher、developer program、free tier。优先**相关性、实际价值及官方可核实性**，不凭关键词本身认定优惠真实；过滤无关电商线报和只有推广码的内容。

不对厂商设置独立重点名单。LINUX DO 要定位“福利羊毛”栏目的当前真实路径；其他站点同样只选择合法可访问的相关栏目，未验证前不编造论坛 URL、RSS/API 或 XPath。

## 存量活动统一复核

监控源仅提供新线索，不对任何特定厂商设置重点名单。每次执行时，**先读取仓库最新 `data/resources.json`**；对所有当前有效（`displayStatus(..., now) === 'active'`）、距 `lastVerifiedAt` **已满 24 小时**的记录安排官方复核，不论记录最初来自哪个论坛或厂商。该阈值按 UTC 精确毫秒计算，而不是日历日期或 Git 修改时间；旧的 `nextReviewAt` 即使更晚，也不能覆盖 24 小时条件。

成功核实后，即使权益没有变化，也记录真实证据与历史，更新 `lastVerifiedAt` 并设置 24 小时后的 `nextReviewAt`；实际额度、资格、地区、期限、配置、收费或活动状态变化须同步写回。官方读取失败时不伪造成功、不刷新时间。所有到期项都要处理或明确列出因限速/失败而积压的项目，不能用“前 5 条”的默认上限长期遗漏活动。

## 信息来源等级

1. **官方证据**：厂商可归属官网、官方条款/价格/API 文档、有效的官方公告。用于核实是否可发布及核定可信度。
2. **官方关联但不完整**：官方社媒/论坛管理员公告，需核对关联身份与正式条款；未证实资格/费用时不能视为 high。
3. **社区/聚合线索**：上述论坛、福利聚合站、第三方文章。用于发现，默认低可信，不能直接标 active。

## 候选信息字段与审查流程

发现队列至少包含 `sourceName`、`discoveryUrl`、`discoveredAt`、`rawTitle`、`providerCandidate`、`officialUrlCandidate`、`category`、`fingerprint`。队列不直接供前端消费。

1. 去重：相同官方活动 URL 优先；备用网址规范化时不要误合并不同活动批次。
2. 官方：先访问普通官网入口，失败才尝试**已授权且可用**的 Firecrawl；不得自动绕过风控或登录。
3. 逐项抽取：权益/价值、资格、地区、时效、真实配置、信用卡与费用，以及核实证据。
4. 标级：缺乏官方证据或关键费用/资格信息时放入待审队列，不自动写成 active。
5. 发现新数据、变更或失效时保留摘要和官方 URL；对到期活动成功复核即使业务条款未变，也必须追加真实证据/核实时间/历史并提交实际 JSON 差异。只有没有新增、变更或成功复核记录时才不提交。

## 发布与频率

按来源服务条款限速，新发现默认单次最多 3 条；存量有效活动必须按 24 小时阈值检查全部记录，逐批处理超时项（没有固定 5 条上限），有积压必须报告。**运行方式为 Skill 驱动**：不实现采集器、不配置 `schedule` 定时 workflow，每次由人工或 Agent 显式发起。成功复核写入 JSON 后，按已获授权的仓库写入流程操作；更新 main 才会由现有 Pages 工作流自动构建发布，PR 仅创建不会直接发布生产站点。

**当前状态**：这份文件仅定义来源和审查方法，不描述已部署的采集程序。项目已决定不实现定时采集器与定时 workflow，来源的可读性、ToS/robots 与限速须在每次运行中实测确认，不得把未验证的域名写成 allowlist。
